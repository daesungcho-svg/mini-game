# 크롬 공룡 게임(T-Rex Runner) 분석 문서

> 목적: 발전된 형태의 공룡 게임을 만들기 전, 원작(크롬 오프라인 게임 및 안드로이드 클론들이 기반으로 삼는 원본)의 구조와 수치를 분석하여 기준선(baseline)으로 삼는다.
> 출처: Chromium 오픈소스에서 추출된 `t-rex-runner` 구현체(`Runner`, `Trex`, `Obstacle`, `NightMode`, `Cloud`, `DistanceMeter` 클래스)의 실제 소스 코드 상수값 기준.

---

## 1. 게임 개요

- **장르**: 무한 러너(Endless Runner), 사이드 스크롤 2D
- **플랫폼 원본**: 데스크톱 Chrome 브라우저의 "인터넷 연결 없음" 에러 페이지에 내장된 이스터에그
- **조작**: 스페이스바 / 위 방향키 = 점프, 아래 방향키 = 숙이기(duck). 모바일/터치 환경에서는 화면 탭 = 점프, 길게 누르기(아래쪽 스와이프)로 숙이기 구현
- **목표**: 장애물(선인장, 익룡)을 피하며 최대한 오래 생존 → 생존 거리가 곧 점수
- **캔버스 규격**: 600×150px (가로로 긴 저해상도 뷰포트), 60fps 기준 로직

핵심 디자인 철학은 "규칙이 극도로 단순하지만 난이도가 끊임없이 상승"하는 구조다. 조작 축이 1개(점프/숙이기)뿐이라 학습 비용이 0에 가깝고, 대신 속도 증가와 장애물 조합으로 긴장감을 만든다.

---

## 2. 캐릭터(T-Rex) 물리 스펙

| 항목 | 값 |
|---|---|
| 캐릭터 크기 (서 있을 때) | width 44 / height 47 |
| 캐릭터 크기 (숙일 때) | width 59 / height 25 |
| 중력(GRAVITY) | 0.6 px/frame² |
| 점프 초기 속도(INITIAL_JUMP_VELOCITY) | -10 |
| 최대 점프 높이(MAX_JUMP_HEIGHT) | 30 |
| 최소 점프 높이(MIN_JUMP_HEIGHT) | 30 (짧게 눌러도 최소 이 높이는 보장 — 일명 "짧은 탭도 구제") |
| 숙이기 시 낙하 가속 계수(SPEED_DROP_COEFFICIENT) | 3 (아래 방향키를 누르며 낙하하면 3배 빠르게 착지) |

**설계 포인트**: 점프 궤적은 물리 기반(속도-중력 적분)이라 즉각적이지 않고 포물선을 그린다. "최소 점프 높이"를 강제해 아주 짧게 탭해도 우스꽝스러운 초저공 점프가 나오지 않도록 보정한 점이 눈에 띈다.

## 3. 속도 & 난이도 곡선

| 항목 | 값 |
|---|---|
| 초기 속도(SPEED) | 6 |
| 가속도(ACCELERATION) | 0.001 (프레임마다 속도에 가산) |
| 최대 속도(MAX_SPEED) | 13 |
| 모바일 속도 보정(MOBILE_SPEED_COEFFICIENT) | 1.2배 (모바일에서 화면이 좁아 체감 속도를 올림) |

속도는 매 프레임 `speed += ACCELERATION` 형태로 선형 증가하다가 MAX_SPEED에서 캡핑된다. 즉 **"기하급수적으로 어려워지는 착시"는 사실 선형 가속 + 장애물 간격 축소의 조합 효과**다. 속도가 오를수록 장애물 최소 간격(minGap)도 속도에 비례해 조정되어, 화면에 장애물이 나타나는 "시간 간격"은 줄어들지만 최소 반응 시간은 일정 수준 보장된다.

---

## 4. 장애물 시스템

| 종류 | width | height | y좌표 | 최소 간격(minGap) | 등장 조건 | 비고 |
|---|---|---|---|---|---|---|
| 선인장(소) CACTUS_SMALL | 17 | 35 | 105 | 120 | 속도 무관(minSpeed 0) | multipleSpeed 4 이상부터 2~3개 묶음 등장 가능 |
| 선인장(대) CACTUS_LARGE | 25 | 50 | 90 | 120 | 속도 무관 | multipleSpeed 7 이상부터 묶음 등장 |
| 익룡(Pterodactyl) | 46 | 40 | 100 / 75 / 50 (3단 높이) | 150 | minSpeed 8.5 이상에서만 출현 | 2프레임 날갯짓 애니메이션(약 166ms 간격), speedOffset 0.8로 살짝 다른 상대속도 |

**게임 밸런스 설계 포인트**
- 게임 시작 직후에는 선인장만 등장 → 규칙 학습 구간
- 속도가 8.5를 넘는 "중후반"부터 익룡이 등장 — 익룡은 높이가 3단으로 랜덤화되어 "서서 피하기 / 숙여서 피하기 / 그냥 지나가기"를 모두 요구, 조작 두 축(점프+숙이기)을 실제로 쓰게 만드는 유일한 장치
- 장애물은 최대 3개까지 한 묶음으로 이어붙을 수 있고(MAX_OBSTACLE_LENGTH 3), 같은 종류가 반복 출현하는 것을 막기 위해 최근 등장 이력을 참조해 중복을 최대 2회로 제한(MAX_OBSTACLE_DUPLICATION 2)
- 장애물 스폰 간격은 `GAP_COEFFICIENT(0.6) × 랜덤값 × 현재 속도 기반 최소 간격` 공식으로 계산되어, 속도가 빨라져도 절대적으로 반응 불가능한 간격은 나오지 않도록 하한선을 둠

## 5. 충돌 판정(Collision Detection)

- 스프라이트의 실제 이미지 박스보다 **약간 안쪽으로 줄인 히트박스(Collision Box)**를 별도로 정의해서 사용 — 그림상 살짝 닿은 것처럼 보여도 판정은 관대하게(player-friendly) 처리
- 캐릭터/장애물 각각 여러 개의 작은 사각형(다중 박스)으로 분할해 판정 정밀도를 높이되, 전체적으로는 "약간 후하게" 튜닝됨 (플레이어 체감 공정성 확보가 목적)
- 판정 방식: 사각형-사각형 교차 판정(AABB) 후, 필요시 더 세분화된 박스로 재검사

## 6. 점수 시스템

| 항목 | 값 |
|---|---|
| 점수 변환 계수(COEFFICIENT) | 0.025 (이동 거리(px) × 이 값 = 점수) |
| 업적/효과음 트리거 거리(ACHIEVEMENT_DISTANCE) | 100점마다 |
| 최고점수(HI) | 로컬 저장(localStorage)에 영속 저장, 현재 점수 위에 나란히 표시 |
| 자릿수 | 5자리(패딩), 자릿수를 넘기면 자리올림 플래시 효과(FLASH_DURATION 250ms × 3회 깜빡임) |

점수는 "시간 생존"이 아니라 **이동 거리 기반**이며, 속도가 빨라질수록 같은 시간에 더 많은 거리를 이동하므로 후반부 점수 상승 속도가 빨라지는 효과가 자연스럽게 생긴다. 별도의 콤보/보너스 스코어링은 없음 — 극단적으로 단순한 단일 스코어 축.

## 7. 낮/밤 사이클 (Night Mode)

| 항목 | 값 |
|---|---|
| 발동 주기(INVERT_DISTANCE) | 700점(정확히는 700 단위 거리)마다 |
| 전환 방식 | 페이드 인/아웃 (FADE_SPEED 0.035, 전체 반전 지속 INVERT_FADE_DURATION 12000ms) |
| 밤 연출 요소 | 화면 색 반전, 달(Moon, 위상 변화), 별 2개(NUM_STARS) |

시각적 변주 외에 **난이도에는 영향을 주지 않는 순수 연출 요소**다. 그러나 일정 거리마다 화면이 반전되며 짧은 순간 시인성이 떨어지는 효과가 있어 은근한 난이도 스파이스 역할도 한다.

---

## 8. 배경 연출

- **구름(Cloud)**: 배경 스크롤 속도의 0.2배(BG_CLOUD_SPEED)로 시차(parallax) 효과, 46×14px, 화면에 최대 6개(MAX_CLOUDS), 등장 빈도 계수 0.5
- **지평선(Horizon Line)**: 600×12px 라인이 반복 타일링되며 스크롤. 미세한 지형 굴곡 텍스처가 있어 "질주감"을 강화
- 배경 요소들은 게임 로직(충돌/점수)에 전혀 관여하지 않는 순수 장식

---

## 9. 게임 상태 관리 & 흐름

1. **대기(Waiting)**: 첫 입력 전 정적 화면, 캐릭터가 제자리에서 깜빡임(눈 blink, MAX_BLINK_COUNT 3)
2. **플레이(Playing)**: 입력 시작과 동시에 스크롤 시작, 속도/거리/점수 누적
3. **충돌(Crash)**: AABB 충돌 감지 즉시 정지, 캐릭터 스프라이트를 "충돌" 프레임으로 전환
4. **게임오버(Game Over)**: "GAME OVER" 텍스트 + 재시작 아이콘 표시, GAMEOVER_CLEAR_TIME(750ms) 동안 입력 무시 후 재입력 허용 (실수로 바로 재시작되는 것 방지)
5. **재시작**: 스페이스/탭 입력 시 CLEAR_TIME(3000ms) 페이드로 초기화

이 상태 전이가 아주 짧은 루프(수 초~수십 초 단위 재도전)를 만들어 "한 번 더" 하게 만드는 캐주얼 게임의 핵심 리텐션 장치다.

---

## 10. 사운드/피드백

- 점프 효과음, 100점 단위 업적 효과음(짧은 비프), 충돌음 정도로 **미니멀한 오디오 피드백**만 존재
- 시각적 피드백(점수 자릿수 깜빡임, 화면 반전)이 오디오보다 비중이 큼

---

## 11. 기술 구조 요약

- **렌더링**: HTML5 Canvas 2D, 단일 스프라이트 시트(sprite sheet)에서 좌표를 잘라 그리는 방식(이미지 로딩 최소화)
- **해상도 대응**: 고밀도 디스플레이(레티나) 대응을 위한 2x 스프라이트 시트 별도 보유
- **게임 루프**: `requestAnimationFrame` 기반, 델타타임을 보정해 프레임 드랍 시에도 속도가 급변하지 않도록 처리
- **클래스 구조**: `Runner`(총괄) → `Trex`(플레이어) / `Horizon`(지형+장애물+구름 총괄) → `Obstacle`, `Cloud`, `NightMode`, `HorizonLine`, `DistanceMeter`(UI) — 관심사가 명확히 분리된 구조

---

## 12. 안드로이드 오프라인 클론에 대한 참고

아이가 플레이한 것은 대부분 이 크롬 이스터에그 원본을 그대로 이식하거나(가장 유명: 크롬 자체의 "공룡 게임"이 이제 정식 앱/미니게임으로도 배포됨) 플레이스토어의 서드파티 클론(`Dino Game`, `T-Rex Runner` 등)이다. 이런 클론들은 위 수치를 거의 그대로 복제하거나, 스킨(캐릭터 교체)·아이템·코인 시스템 등을 얕게 추가한 수준이 많다. 핵심 루프(점프/숙이기, 선형 가속, 거리=점수)는 대부분 동일하다.

---

## 13. 확장 설계 시 고려할 지점 (다음 단계용 메모)

원작의 "제약"이자 "확장 포인트"가 될 수 있는 부분들:

- **조작축이 1.5개뿐**(점프+숙이기) → 새 조작(대시, 이중 점프, 슬라이드 취소 등) 추가 여지
- **장애물 3종 고정**(선인장 2종+익룡 1종) → 새 장애물 타입, 파워업, 방어 아이템 여지
- **단일 점수 축**(거리만) → 콤보, 아이템 수집, 스테이지/미션 시스템 여지
- **난이도가 순수 속도 가속에만 의존** → 패턴 기반 난이도(장애물 조합 시퀀스 디자인), 랜덤시드 기반 일일 챌린지 등 여지
- **연출이 낮/밤 반전 하나뿐** → 배경 테마, 계절/지형 변화, 보스 등장 등 여지
- **오프라인 로컬 최고점만 존재** → 리더보드, 리플레이, 업적 시스템 여지
